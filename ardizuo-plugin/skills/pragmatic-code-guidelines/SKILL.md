# Pragmatic Code Guidelines

This is an original local development-focused adapter, not an official third-party skill.

Prefer correct straightforward code, clear naming and simple interfaces. Use existing utilities before adding abstraction. Avoid speculative generalization and premature optimization. Define success criteria, use tests and measure before major performance refactors. Reuse repo conventions. This is an original local guide, not a transcription or endorsement from a named author.
