# Ardizuo development workflow baseline

Apply this as a portable user-level development rule; project-specific instructions may be stricter.

1. **Triage:** clarify goal; inspect repository and existing solutions before changing files.
2. **Contract:** define scope, acceptance criteria, non-goals, tests and file ownership.
3. **Dispatch:** use specialist agents and parallel waves only when materially useful; never claim delegation unless the agent tool actually ran.
4. **Review:** inspect changed files, test what was changed, check security/reuse/dead-code issues, and disclose gaps.
5. **Ship:** summarize actual verification, Git diff review, documentation and rollback considerations; do not claim unrun commands passed.

Prefer small, reversible edits and evidence-backed status. Do not commit, push, deploy, install dependencies, alter account settings, or write knowledge-vault notes without user approval. Do not add any social-media automation or integrations.
